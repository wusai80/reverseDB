# 迁移优先：不修改分析器的跨模块基线

2026-11-06。研究重点从当前案例的分数改善，转为表示和评分能否跨模块复用。首先完成了一次冻结分析器的真实反编译源码检查：NewOrder、Payment作为已有开发模块，Delivery作为本轮迁移目标；OrderStatus、StockLevel暂不纳入本轮提取。

**结果是局部结构可以迁移，但尚不具备端到端风险评分的迁移条件。** 本轮没有候选改写、目标行为标签或模型预测，不能报告分类准确率，也不能把依赖提取覆盖率当作泛化准确率。

## 不适配目标，先测实际覆盖

冻结当前JdbcBoundaryExtract、inspect_binding和跨层recover的代码及源文件哈希，使用完全相同的接口依次分析三个模块。未新增目标模块名称判断、SQL槽位映射、API摘要或解析分支。

| 静态测量 | NewOrder：开发 | Payment：开发 | Delivery：迁移目标 |
| --- | ---: | ---: | ---: |
| PreparedStatement声明得到有限SQL集合 | 10/10 | 10/10 | 7/7 |
| setter位置的值表达式在已有术语范围内 | 23/35 | 24/38 | 22/23 |
| 现有绑定检查接口成功 | 21/30 | 24/38 | 22/23 |
| 时间绑定恢复到SQL写入列 | 1/1 | 1/1 | 0/1 |

分母口径不同：setter按源码调用位置计数；绑定检查按现有API要求的不同`(方法, 槽位)`组合计数，同一方法中不同语句的同槽位会被合并并可能判为不唯一。均为静态位置数，不是业务执行次数、独立样本或所有可达路径数量。

Delivery两个断点有具体来源：

1. `updateBalanceAndDelivery`第1位传入`BigDecimal.valueOf(...)`。已有值表达式提取器没有该调用的语义摘要，保留unknown；不能用“同样是金额”直接猜它与其他转换等价。
2. `updateDeliveryDate`的时间表达式和第1位JDBC绑定均能恢复，SQL文本也能恢复，但`UPDATE order_line SET OL_DELIVERY_D = ? ...`不在现有跨层写入列恢复的受支持形状中，记录`unsupported SQL shape`。NewOrder、Payment此前成功的是INSERT路径。

第二点不是发现Delivery真的缺少依赖，而是分析器无法表达该依赖。产生一个局部图或压缩DAG，不代表已经恢复整个模块的能力和效果。

## 迁移评估的边界

将三个问题分开计量：

- **表示覆盖**：同一提取过程能否在目标代码上恢复所需事实；unknown和未支持输入必须保留。
- **评分迁移**：共同的候选相对原实现表示就绪后，只用开发模块拟合模型，固定权重，再预测目标候选。
- **语义验证**：预测冻结后运行目标的端到端比较，以完整响应、逐请求观察和九表完整数据产生标签。未发现差异仍不是全能力等价。

本轮完成的是第一项的基线测量。现有概率实验基于人工原语或少数选定绑定，尚没有覆盖不同模块的共同候选表示；因此当前结果中`candidate_pair_features`、`risk_score`和`transfer_accuracy`都为null，没有赋零或临时拼分数。

Delivery未参与当前NewOrder/Payment特征设计，但其源码和应用行为在项目历史中已出现，不能称为未见项目或独立盲测。它现在的失败原因已经公开，后续若根据它修改表示，Delivery必须转为开发材料，不能将重测包装成独立迁移成功。OrderStatus、StockLevel只是本轮预留目标，也不能自动等同于完全未见的软件；跨项目泛化仍需另一项目。

## 接下来的研究约束

目标是一个跨模块共同表示：用值定义、变换、消费以及可观察数据库效果连接候选与原实现，再让模型学习这些关系的变化。模块名、表名和特定JDBC槽位可用于追溯和对应，不能替代语义特征或直接充当风险规则。

本次暴露的具体问题是：**同一类持久化值依赖，能否跨INSERT和UPDATE等语法形式进入同一个表示？** 后续首先研究这个小问题及未支持变换的明确表达，不继续为Payment增加独有条件特征，也不开始完整静态分析平台工程。

评估协议已经固定以下要求：

- 按模块整体留出，原版、变体、修复和请求场景不跨训练／测试拆分；更多请求不是更多独立候选。
- 特征、归一化、权重及预测在目标行为标签生成前固定；不根据目标结果调阈值或选特征。
- 同时报告覆盖率、弃权、相同可评分集合上的Brier／log loss与训练先验，以及低风险预测漏掉的错误候选；不能通过只评分容易案例制造进步。
- 完整数据保留，明确故障和未执行后缀；不把暂未观察到的路径当作可删。
- 迁移失败即记录失败；若针对它适配，进入新的开发阶段并另选评估目标。

本轮固定检查结束：三个模块各一次新AST提取及图恢复，25个证据文件哈希核验；未改分析器、未拟合、未读取行为标签、未运行数据库、未自动删除模块。

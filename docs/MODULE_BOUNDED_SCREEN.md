# 保留完整能力与数据的一次模块筛选

2026-11-05。**本次有限范围内没有符合准入条件的新删除候选。** 共审查九个职责区域：八个可见输出、控制、状态或资源依赖；一个存在尚未证明冗余的锁效果。按既定停止条件结束，不扩大搜索或继续调分。

## 范围与证据

从已有两个来源的已知入口向相关调用扩展一层职责审查：

- Paperless：`BulkDownloadView.post`、三种导出策略及直接关联的文档版本解析。
- Saleor：`add_variants_to_checkout`、相关国家同步、行匹配、增删改、库存预留与 bulk 写入包装器；仅为检查包装器共享性，定位另一处静态调用。

这不是两个完整仓库的穷尽审计。入口的能力选项继续保留，合法文档、版本、金额、数量和数据库行不因测试样本缩小。未将诊断、资源、并发或错误效果默认为可以忽略。

本轮读取九份源文件，并逐字节核对锁定 commit 的 Git blob；源码副本与哈希已归档。只建立静态调用路径证据，没有新运行完整应用；因此不把“代码路径上存在调用”表述为已观测执行次数。已知依赖足以让本轮不准入删除，无需为了失败候选启动数据库。

| P2 | 根文档与最新版本解析 | 返回对象决定实际导出的版本和内容 | 保留 |
| P3 | 命名策略与 ZIP 写入 | 无返回值的 `add_document` 仍修改响应所用 ZIP；命名、碰撞处理被观察 | 保留 |
| P4 | 临时文件建立、描述符关闭与清理 | ZIP/响应依赖文件，关闭和清理影响资源生命周期 | 保留 |

## 最值得保留的发现：值无用，效果仍可能有用

Saleor 的两个位置具体说明了为什么不能只按返回值裁剪模块。

第一，`country_code = checkout.get_country()` 的结果仅在条件库存预留分支中使用，但 `get_country` 在地址国家与已存国家不一致时，调用 `set_country(..., commit=True)`，后者执行 `save(update_fields=["country"])`。即使某次请求不进入预留分支，也不能直接去掉整个调用；保存字段是另一条需求路径。这里没有构造“国家总相同”的数据限制来制造可删条件。

第二，`checkout_lines_bulk_update` 把锁查询结果赋给 `_locked_lines` 后不读取它，但查询构造显式使用 `select_for_update`。忽略返回值会漏掉锁效果。外层 `add_variants_to_checkout` 也请求锁定行，因此**特定调用点的再次锁定存在可研究的重复效果线索**；它尚不满足本轮删除准入条件，也不能由此宣称锁操作在所有上下文都必需。

这一线索的最小问题是：外层已建立的效果是否完整覆盖内层请求的效果？要肯定回答，至少需绑定同一事务/连接、所有合法路径的目标行覆盖、锁模式与存续期、调用/保存点期间变化、错误与并发观察。`calculations.py` 中还有另一处包装器调用，无法将某一个调用点的条件推广成全局删掉包装器保护。

当前只记录上述义务，不继续研究 ORM 对象去重、不缩小数据域、不删除锁查询，也不将其排入自动执行队列。资源、状态和锁效果的追踪比追加一个概率分数更能解释本次筛选结果。

## 停止结论

本阶段按[收敛审查约定](MODULE_CONVERGENCE_REVIEW.md)结束：零候选准入、零新增标签、零应用/数据库运行、零拟合、零删除、零性能样本。原有四个条件负例和 OrderStatus 的历史加速证据均不变。

“本范围无合格候选”不等于整个软件不可优化，也不等于模块删减方法已经失败。它说明当前这两个入口周边的工作大多有能力消费者，剩余线索需要效果覆盖论证。后续如果继续，应先讨论是否把这个一般性的效果覆盖问题选作研究对象；本轮不自动扩范围或进入新一轮试探。

# 跨事务筛选：用外键约束消除重复的存在性检查

2026-11-05。限定筛选五项实际执行的职责，覆盖 NewOrder、Payment、Delivery、StockLevel 四个事务。四项保留，一项完成真实删减验证：从反编译 `NewOrder` 删除 `getWarehouse` 方法及其唯一内部调用。该方法原本执行一次仓库存在性查询；它的检查条件可以由前置客户检查和有效外键链推出。

本轮的新增证据是**程序控制顺序与数据库完整性约束联合支持删除**。这与之前的入口不可达、展示返回值被丢弃两种理由不同；不是以样本中总能找到仓库作为理由，也未声称此原理本身是新的学术理论。当前仍是人工绑定候选与契约，尚未实现通用约束求解或自动模块发现。

## N2 的具体论证

反编译事务入口的顺序为：

```text
getCustomer(conn, w_id, d_id, c_id)  // 无客户则抛错；保留
getWarehouse(conn, w_id)           // 只判断仓库是否存在；候选
getDistrict(conn, w_id, d_id)      // 读取订单号并加锁；保留
后续订单与库存写入                 // 全部保留
```

`getCustomer` 与 `getWarehouse` 使用同一连接和同一 `w_id` 参数，中间没有写入或参数修改。前者正常返回意味着已找到指定客户；后者查询 `W_TAX`，但不读取税值，仅以 `rs.next()` 判断存在性。

实际恢复的数据库包含以下有效、强制执行、非延迟外键：

\[
Customer(c\_w\_id,c\_d\_id)\to District(d\_w\_id,d\_id),
\qquad District(d\_w\_id)\to Warehouse(w\_id).
\]

所以在同一可见快照和相同键绑定下：

\[
getCustomer(w,d,c)\text{ 正常返回}
\Rightarrow \exists C(w,d,c)
\Rightarrow \exists D(w,d)
\Rightarrow \exists W(w).
\]

由此排除的是仓库检查中的“没有该仓库”业务分支。仍需额外要求该查询正常完成、没有保留观察所需的读取效果；外键无法证明网络、JDBC、资源或数据库执行永不失败。

此论证针对满足模式约束的任意键和完整数据，不依赖某个客户值、具体行数或测试覆盖率。`getCustomer` 自身不能用同样理由删除：外键只从已存在的子行推出父行存在，不保证任意输入客户 ID 存在。

## 环境前提与实现边界

- 前置检查必须支配被删除调用，参数绑定相同，中间无破坏前提的写入，使用同一事务可见性。本轮原有运行器使用 SERIALIZABLE，工作负载串行。
- 检查两条外键的关系和列定义、`convalidated`、`conenforced`、非延迟属性、相关约束触发器启用状态及 `session_replication_role=origin`。
- 参与关系为当前固定应用使用的普通业务表，无行级安全策略。本轮没有动态换 schema、临时同名表、外部 DDL 或插件。通用准入器还需解决任意环境的关系名称解析与效果证明；不能把实验检查当作完整生产环境防护。
- SQL 字段 `stmtGetWhseSQL` 及其余九项初始化全部保留。候选只删除一个方法和一行调用；适配器、其他事务、数据库模式与业务数据均不变。
- NewOrder 原终端 `run` 没有替换为拒绝桩；本轮验证范围仍是既有应用入口，未声称完成原终端的全部测试。

模式准入检查由实验探针执行，**没有插入候选 JAR 形成运行时自动回退**。候选只能在已核验的条件下使用；约束缺失或未知时应保留原版。

## 固定运行结果

原版与候选版各运行既有四个场景、62 条固定命令，共 **124 条业务回放命令**。每个场景从完整快照独立恢复，保留原有顺序、时钟和数据域。

- 每组均为 50 次提交、4 次业务回滚、8 次输入拒绝。
- 完整响应、逐步业务观察、初始/最终九表完整行哈希及一致性约束的 **20 组比较全部一致**。
- 精确移除目标 SQL 的参数绑定、执行与取行片段后，其余 JDBC 事件全部逐项、逐序相同；被移除的原始事件单独保存，没有将所有读取或所有异常整体忽略。
- 目标仓库查询共减少 **14 次**：baseline 3、holdout 9、transaction_edges 1、delivery_edges 1。其中包括后续因非法商品回滚的事务，原业务回滚继续保留。
- 一个商品行的诊断事务读取数 **8 → 7**，完整响应一致。未测延迟或吞吐，不能将查询次数变化当作加速百分比。
- `NewOrder.class` 从 10,855 字节变为 10,418 字节，减少 437 字节；其他 JAR 条目逐字节相同，实际类加载来源已核验。

## 前提与错误的反例检查

每次独立恢复的数据库均执行以下控制，探针完成后全九表状态与探针前一致：

1. **有效外键：** 满足准入条件。
2. **缺少地区→仓库外键：** 在仅属于实验的事务中临时删除该约束，准入结果为 false；不在这个状态下执行候选，随后回滚并确认约束恢复。没有删改客户、仓库或其他业务行。
3. **被删仓库查询故障：** 注入 SQLSTATE `58000`，原版报错，候选版成功。明确保留不等价反例，限定正常执行契约。
4. **保留客户查询故障：** 两版产生相同错误，未把客户校验与错误控制一起删除。

诊断事务的临时写入全部回滚，诊断时钟固定；诊断调用不计入 124 条业务回放命令。四个场景的完整业务序列仍单独执行。

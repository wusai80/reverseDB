# 加入效果特征后的固定对照

2026-11-04。在上一轮冻结的 24 个有限程序变体上，增加六项从源码结构与契约提取的效果特征。保持标签、分组、拟合方法和参数不变，比较预先定义的三组特征。

**开发集上的分组 Brier 分数从 0.2503 降到 0.1922。** 这是更多语义信息有用的初步证据；由于特征是在看过旧结果后设计的，本轮不是新的独立泛化验证，也未替换真实应用评分。

## 新增特征

提取器读取冻结的有限程序源码，使用 Python AST 按显式程序配置专门化。契约中某输入仅有一个合法值时，允许常量传播；这不是从有限探针碰巧使用的值推断输入范围。它不执行原版/删减版比较，也不接收真标签或反例。

| 特征 | 提取含义 | 不代表什么 |
|---|---|---|
| `module_may_write` | 模块中有赋值或增量更新，包含局部与堆状态 | 不代表写入一定影响保留能力 |
| `module_may_raise` | 专门化后模块中保留显式抛错动作 | 不是完整异常摘要，未覆盖任意外部调用 |
| `observable_write` | 写目标通向保留返回观察中的绑定或对象 | 零增量也会被标记，因此不是必要性标签 |
| `alias_write_to_observation` | 堆写通过直接别名通向观察对象 | 不处理任意指针/容器或跨过程别名 |
| `neutral_update_only` | 模块写入均为支持范围内的 `+=0` 或与初始常量相同的赋值，且没有模块 raise | 仅适用于本轮有限整数/状态语言，不推到任意 Java 对象 |
| `retained_similar_action` | 模块之后仍保留语法相同的写入或抛错动作 | 相同语法不证明相同条件、时序或可完全替代 |

资源生命周期在该有限语言中体现为可观察对象的状态写入与后续清理动作，不根据“资源”机制名称直接赋特征。真正跨模块的共享调用还没有在本轮数据中成为独立训练字段；保留同类后续动作不等同于证明共享依赖。

初始化的直接别名与模块之前的独立复制被区分；模块之后的复制需要额外时序分析，本版直接拒绝支持。提取器只面向这份固定有限程序语言，不是通用 Python 或 Java/JDBC 效果分析器。

## 特征来源与标签隔离

输入接口只有：源码、固定程序配置 `family/v`、显式契约域 `x/flag`。配置用于选择程序中已经存在的分支，不用于查表填写特征或读取标签。模型只收到特征布尔值；机制名称和变体号仅用于来源追踪与整组留出。

每个候选保留模块动作源码行、后续动作、观察绑定和专门化代码，便于审查特征究竟来自哪里。

新增八项检查包括：

- 区分可见写入与局部临时写入。
- 区分别名与独立复制；改变源码中的复制关系会改变特征。
- 根据完整契约的单值域消去不可达抛错。
- 识别零增量和同值赋值；改变初始值会使同值判断失效。
- 识别保留的同类动作。
- 拒绝向提取接口注入标签或反例字段。
- 局部变量重命名后特征不变。
- 修改穷举标签生成函数后特征不变。

全部八项通过。检查只说明受支持语法上的行为，不能证明完整程序效果恢复。

## 固定的消融对照

三个方案在运行前写入[协议](../prototype/module_pruning/effect_feature_protocol.json)：

1. **旧两项**：返回值弃用、有限探针通过。
2. **效果存在性**：旧两项，加可能写入、显式抛错。
3. **效果上下文**：前四项，加观察关联、别名关联、中性写入、保留同类动作，共八项。

复用同一份冻结标签与完整域比较记录，没有生成新真标签。保持六个“留出完整机制组”的划分，以及每组总权重为 1、α=β=1 的联合格平滑校准。旧两项结果逐值复现上一轮，确认没有通过更换拟合器或数据制造改善。

指标越低越好，先在各留出组内取平均，再对六组平均：

| 方案 | Brier | 对数损失 | 未见组合回退次数 |
|---|---:|---:|---:|
| 训练组必要比例基线 | 0.250000 | 0.693147 | 不适用 |
| 旧两项特征 | 0.250333 | 0.693814 | 3 / 24 |
| 加效果存在性 | 0.235778 | 0.664490 | 3 / 24 |
| 加效果上下文 | **0.192249** | **0.575803** | 9 / 24 |

仅检测写入和抛错有一定改善，但不足以区分对外可见状态与局部临时状态、别名与复制、实际更新与零增量。进一步表达这些关系后，六个留出组的 Brier 均低于旧两项方案；这支持继续研究模块的效果边界，而不是仅增加运行次数。

同时，更多特征使证据组合稀疏。完整方案有 9 个候选在训练组没有相同特征组合，仍回退到训练必要比例。没有隐藏回退、对这些候选追加训练，或尝试其他模型来追求更好数字。

## 结论及适用边界

本轮说明，**模块必要性的评分值得加入“效果如何传播到保留观察”的特征**，单看“发生了某种操作”不够。该结论来自有限程序开发集上的受控对照，未做显著性论证。

特征设计已经参考上一轮结果，因此再次使用相同分组留出只能算开发阶段对照，不能充当全新保留测试。数据仍是人为平衡的六种机制变体，不代表真实软件的必要模块比例。

真正需要进一步验证的是：同样的特征能否从新的程序及真实反编译产物中可靠恢复，并在未参与设计的案例上保持区分力。完整的数据库/外部库效果摘要仍未解决。本轮没有把有限 Python 特征冒充为已实现的 Java/JDBC 分析。

真实 `risk_model.json` 前后摘要相同；所有拟合表仅允许有限程序域，对真实 OrderStatus 输入仍返回 abstain。模块删除不会由本轮评分触发。

本轮在三组固定对照完成后结束，不继续调参、加特征或增加业务负载。

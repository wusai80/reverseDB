# 应用—数据库联合优化：两个受限研究问题

2026-11-04。用户要求从工程调优转向问题定义。本文件替代上一轮“逐事务减少 JDBC 调用”的推进顺序；旧分析保留为实例证据，不按其列表逐项实施。

本轮选择两个互补问题：**跨语言中间结果的关系化**与**消费者需求驱动的计算域缩减**。前者改变计算的表达和位置，后者改变必须计算的范围。缓存、连接池、PreparedStatement 复用、索引调整以及工具自身加速均不作为研究对象。

这是研究问题与验证协议，不是新颖性结论。已有 grouped join、子查询与谓词下推必须作为强基线；不能把一个常规 SQL 改写包装为创新。

**理论基础更新：** 按用户建议，P1 采用带多重集、聚合、顺序、类型及观察条件的扩展关系代数；P2 分为语义需求传播和有约束的最低成本计划选择。背包用于独立可选策略的特例，一般共享依赖用 AND–OR 图表达。见[理论模型、相关原始文献与小型精确模型](APP_DB_THEORETICAL_MODEL.md)。这一求解层不新增第三个研究问题，也不替代程序等价义务。

## 共同模型与正确性目标

令 S 为满足约束 κ 的数据库状态，x 为合法应用输入，P 为包含 SQL 与应用计算的有限程序区域，H 为该区域之后的消费者。κ 包含键/NULL/类型、有效关系与权限谓词、参数、快照、可观察效果以及消费者契约；它不是某一组测试数据。

以 `Obs(H[P], S, x)` 表示完整可观察结果：有类型的返回值及顺序、业务错误结果、持久状态变化和外部业务效果。内部查询文本、调用次数和耗时不要求相同。不同数值类型、NULL 与 0、列表排列、拒绝与成功均不可随意归一化。

对分析器 A 和变换 T，要求：

```text
A(P, H, κ) = accept
    ⇒ ∀ S ⊨ κ, ∀ x ∈ Xκ:
         Obs(H[P], S, x) = Obs(H[T(P)], S, x)
```

首版研究域为固定快照、无相关自写入、无 volatile 表达式及外部副作用的只读区域。查询/网络故障、取消和资源耗尽不在该首版等价命题中；这是明确的理论模型限制，不代表任何真实调用点已经获准忽略故障。缺失实体等应用逻辑错误仍须建模，或以可核验前置条件排除。未经绑定的实际调用点保持原路径；不把旧 B1 异常豁免自动沿用。

用带类型和效果标注的数据依赖图描述区域，节点包含查询、解码、纯应用计算、分支、编码和消费。程序类/函数边界不决定区域大小。任何未知的动态调用、结果逃逸、权限决策或事务边界都阻止跨越。反编译是获取候选图的来源，JDBC trace 用来核对路径，不代替全输入条件。

## 问题一：跨语言中间结果何时可以关系化？

### 输入、输出与优化目标

输入为 `(P, H, κ)`。P 存在以下数据流，其中 Decode/Encode 具有具体的应用与驱动类型语义：

```text
a = Decode(Q1(S, x))
b = f_app(a, x)
v = Decode(Q2(S, x, Encode(b)))
return H(v)
```

目标输出为 `(Q*, h*, obligations)`：数据库表达式 Q*、必要的残余应用计算 h*、尚须核验的条件。若条件闭合，满足：

```text
Obs(H[v], S, x) = Obs(H[h*(Decode(Q*(S, x)))], S, x)
```

同时消除至少一条“数据库结果被应用物化，再编码回后续查询”的依赖边。不是强求整个应用下推，也不是单纯寻找 SQL 最少的实现。比较完整成本：

`C = C_database + C_app + C_transport + C_analysis/validation`。

各项需在明确的重复使用次数下计入；消除边只是结构性目标，不保证 C 降低。

### 受限求解范围

仅研究两种已有实例形状，不构建任意程序的关系化编译器：

1. **标量回传**：查询得到标量，经受限、确定的算术计算后成为另一查询的过滤参数。StockLevel 是实例。
2. **键值映射回填**：分组聚合被构造成 map，再作为 CASE/关联值回填后续查询。Paperless 的既有计数实验是实例。

候选区域必须闭合：被移除的应用值没有未建模消费者。类型桥接、缺失分支、键的唯一性、多重集与 NULL 必须进入义务，而非依赖反编译变量名或测试中的值。

标量实例的核心条件是：对所有可达 a，存在数据库表达式 f_db，使 `Encode(f_app(Decode(a), x))` 与 `f_db(a, x)` 在消费位置具有相同语义。缺失行单独建模，不把不存在的标量默认为 0。Java int 溢出、SQL NULL 或 float/decimal 转换无法对齐时拒绝该规则。

映射实例设 G 为每键唯一的聚合关系，M 为应用 map，T 为目标多重集。若缺失默认值为类型化 0，则：

```text
Decorate(T, M) = Project(T LEFT JOIN G, original_fields, coalesce(G.n, typed_zero))
```

证明逐一对应 T 中每次行出现：匹配键得到同一聚合值；缺失键得到同一默认值；G 的键唯一保证不扩行。完整旧契约见[聚合回填契约](AGGREGATE_REATTACH_CONTRACT.md)。该恒等式已经有条件化论证；新工作不能把再次跑通这一等式当作新的研究结果。

### 要回答的研究假设与可证伪结果

**H1：** 在上述两种受限形状中，一组显式的类型、存在性、数据依赖及效果条件，足以支撑统一的“关系化/保留应用计算/拒绝”判定接口，减少按业务函数手写判断的需要。

验证分别记录规则适用与拒绝的原因、需人工补充的义务，以及候选成本。若仍必须为每个实例写专用识别和正确性规则，则不能声称统一机制；若语义通过但成本更差，记录为可关系化但无收益。

## 问题二：能否由最终消费者反推最小必要计算域？

### 定义：消费者充分需求

设 T 为目标行多重集，L 为保留权限/软删除等谓词后的有效关联多重集，g(L) 为按键的聚合映射，D(T,g(L)) 为逐行装饰，H 为最终消费者。

令 Δ 是需求分析生成的关系表达式，`KΔ = Δ(S,x)` 为所需键集；令 `L|KΔ` 表示 L 与 KΔ 做半连接，即保留这些键的全部有效关联行。称 Δ 对 H **充分**，当且仅当：

```text
∀ S ⊨ κ, ∀ x ∈ Xκ:
  Obs(H(D(T, g(L))), S, x)
    = Obs(H(D(T, g(L|KΔ))), S, x)
```

这不是“页面外的数据没用”。L 的完整数据与能力保留；只在本次消费者不依赖的区域省略派生计算。新请求、更换排序/过滤/消费者时重新求需求。

程序绑定进一步明确：上述公式针对一个聚合生产者。多生产者程序须分别绑定 `Δi`，并检查联合替换后的完整 Obs 等价；同一页面键集不能无条件套用于所有聚合。需求还须区分目标行/键与派生值：需要行的 ID 不一定需要其计数，省略计数不允许删除该行。真实 Tag 接口的例子见[程序绑定](APP_DB_PROGRAM_BINDINGS.md)；首版求解范围仍是单生产者的有限消费者语法，不新增递归树规则。

目标是在可分析的表达式族 F 内找到充分 Δ，减少参与聚合的关联行/分组和中间结果，并比较总成本。**不声称能求任意程序的全局最小需求集**；求 Δ 本身的查询与计算也计入成本。

### 一个可证明的受限规则

若 H 恰为“按原有充分确定的基字段排序/过滤/分页，再输出选中行及其计数”，选择算子 B 完全不依赖聚合结果，且无别的聚合消费者，则令 `W = B(T)`，`KΔ = distinct keys(W)`：

```text
B(D(T, g(L)))
    = D(W, g(L|keys(W)))
```

等号为完整有序结果相等，W 中重复目标行仍保留。证明分两步：B 不依赖装饰值，因此选择的原行出现及顺序相同；每个被选中键的全部有效关联行都被半连接保留，故聚合值相同。keys 去重只用于成员判断，不去重 W。

证明还要求被省略的聚合/解码对原计算域总是有定义且无业务副作用。例如未展示行原本可能触发的数值溢出，不能因优化而静默消失。复杂序列化、树构造、总计字段或 fallback 使用全量计数时，H 必须包含这些消费；不能只看可见页面。

### 必须拒绝的相近结构

- **按计数排序后分页**：先按基字段取页再算计数，可能漏掉真正的第一名。
- **按计数过滤后分页**：先取页可能留下错误成员或不足的页长。
- **部分排序**：同名行缺少原有确定次序，不能给候选单独加主键来制造等价。
- **存在全局计数消费者或 map 逃逸**：最终页面不是完整观察边界。
- **跨快照取页和聚合**：即使各步规则正确，也可能使用不同输入。

计数排序将来可能使用上界或渐进计算，但本轮不引入第三个问题。未知依赖一律返回“需求未建立”，不靠补充测试准入。

### 要回答的研究假设与可证伪结果

**H2：** 对有限消费者语法（基字段过滤、确定排序、分页、投影与逐行装饰），可以沿应用—查询数据流反向传播需求，产生充分的键关系；对聚合依赖和未知消费保守拒绝。

如果当前调用点的消费者全部无法闭合，应报告没有适用实例；不能为获得收益而改接口排序。Paperless 的真实名称排序、分页与树消费者仍未准入，既有主键序区域也不能冒充完整 API。

## 两个问题如何区分并联合验证

| 维度 | P1：关系化 | P2：需求缩减 |
|---|---|---|
| 保持什么 | 原计算域与业务观察 | 最终消费者观察 |
| 改变什么 | 中间值表示与计算位置 | 本次派生计算所需关系域 |
| 可能只减少什么 | 应用物化/重编码/跨层传输 | 聚合输入与分组数量 |
| 独立失败原因 | 类型桥接、缺失值、效果不等价 | 消费依赖、顺序或省略计算不安全 |
| 与已有成果关系 | 既有 map/CASE 是局部基础，不重计创新 | 既有绑定器没有建立完整消费者需求 |

采用四臂消融：原程序、仅 P1、仅 P2、P1+P2。仅 P2 保留应用 map/回填结构，只收缩聚合输入；仅 P1 在完整域内关系化。组合是否获益须测量，不预设叠加。另设同契约的人工 grouped join/子查询/合法下推强基线，不以故意较差的 SQL 为对照。

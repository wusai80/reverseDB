# 当前可处理路径的执行对照

2026-11-05。已对当前能处理的局部条件、一次跨方法传递和已有反射桥进行**实际 JVM 执行验证**。最终一轮为固定 79 个用例、四个版本，共 316 次夹具调用：正确删减版本与原版的全部观察一致；两个故意错误的删减版本均产生反例。30 项核验通过。

本轮测试的是冻结分析夹具及隔离的真实桥方法，不是完整 TPC-C 应用或数据库；未扩展分析器支持范围，未改生产代码、模型、业务数据或功能选项，也没有测性能。

## 测什么、怎样观测

复用已归档的三个 Java 夹具，不重新拟合或修改它们的分支规则：

- `PathConditionFixture`：方法内条件冲突、合法替代分支和 switch。
- `InterproceduralFixture`：调用方条件、实参/形参关系、共享目标和重载。
- `ReflectionTransferFixture`：已有反射桥的调用、参数对应及失败边界。

只在隔离副本中把原本为空的 `hit()` 改成计数并记录调用者源码位置。各版本采用相同插桩，逐次清空计数和轨迹；观察包括三个计数器、命中位置列表、正常 void 返回或异常、异常类与消息。**这里把命中事件明确作为测试观察，错误删减反例针对这个夹具契约，不冒充原始业务功能的必要性标签。**

桥执行的是冻结适配器中 `TpccApp.invoke` 的原方法文本，SHA-256 与已有桥契约一致，放入同包的最小外壳中编译。没有启动应用框架或连接数据库，因此只验证该方法的实际反射行为。

布尔用例覆盖所选入口的全部布尔组合；字符串固定为 null、east、west、未见普通字符串、空串和未见 Unicode 字符串。顺序固定，不根据结果追加输入。字符串样本不是完整值域，运行一致不能代替全输入证明。

## 四个版本与结果

| 版本 | 改动 | 与原版不同的用例数 |
|---|---|---:|
| 原版 | 仅加入共同的命中观察 | — |
| 支持范围内的局部删减 | 依据冻结条件证据，仅删除四个自身条件矛盾的 `hit()` 调用表达式；保留条件求值和方法定义 | **0 / 79** |
| 错误：全局删除共享目标中的调用 | 因某个 caller 上下文不可行，就去掉 direct/reflection 的共享 sink 内命中调用 | **4 / 79** |
| 错误：把未知当作不可达 | 去掉直接与反射的可变参数方法中的命中调用 | **2 / 79** |

正确删减只用于隔离副本，没有把跨方法上下文结论升级成全局删除。四个局部位置分别是布尔相反条件、字符串相反值、switch 标签冲突，以及已矛盾的布尔条件下再嵌套未知条件。

79 个原版用例中，68 个正常完成、11 个产生预期异常。正确删减保留了所有异常类与消息，包括 null 字符串的条件求值异常。条件体不可达不意味着可以删掉条件求值。

## 静态判定与实际轨迹的对应

- 四个局部排除位置没有出现在命中轨迹中。
- 五个直接调用、四个反射调用的“不可行上下文”均按具体 caller 和 callee 的源位置核对；在对应固定输入下没有命中被排除的位置。
- 同一个 sink 从合法替代 caller 进入时仍产生命中；布尔和字符串重载分开按源码行核对。
- 六个未知控制用例实际会命中：包括形参改写、反射打包参数、静态 Object 参数、数值拓宽和目标可变参数。这说明分析器返回 unknown 不代表不会执行，也不代表程序必然出错。

两个错误版本的反例包括：

| 错误做法 | 反例 |
|---|---|
| 全局删共享 sink 中的调用 | `direct.allowed(false)`、`reflection.allowed(false)`、直接传 false 字面量、打包 false 参数；原版各命中一次，错误版不命中 |
| 把未知当作死路径 | 直接与反射目标都将参数从 true 改成 false 后进入分支；原版命中，错误版丢失命中 |

这些反例验证测试能够发现错误的删除规则；不意味着测试覆盖了所有错误变换。反射的歧义、继承方法缺失、类型错误、null 参数包、目标抛异常和拆箱错误也在固定矩阵内实际执行，均与预期一致。

## 轨迹来源核验与复验

首次执行的计数、异常及版本比较通过后，复核发现内部类运行时名称使用 `$`，而源码符号使用 `.`。已统一记录格式，并增加三类夹具的“每个命中位置必须存在于冻结源码”检查，以及 direct/reflection 合法替代上下文的正向位置匹配，避免对不可行位置的比较空通过。

按完全相同的 79 用例和四版本复验后，最终 30 项检查通过。首次档案保留；两轮合计 632 次物理夹具调用，但只计同一个 79 用例矩阵，不能当成 158 个独立样本或两次独立泛化验证。

## 结论与边界

当前支持范围内，静态条件排除与执行轨迹一致，四处局部删减在固定矩阵中保持观察，误删共享目标或未知路径的版本被检出。**可以保留这部分实现作为已通过小规模执行验证的原型。**

不能据此宣称真实业务模块已可删、任意字符串输入均等价、完整数据库能力已验证或获得加速。未知部分继续保留，本轮到此结束，不自动扩展输入矩阵或求解器。

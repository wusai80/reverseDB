# 模块风险评分：第一轮校准试验

2026-11-04。完成真实证据审计和一轮固定的受控校准试验。**经验校准改善了旧手工分数，但没有超过简单的训练集必要比例基线，因此不替换现有真实应用评分。** 真实应用概率尚未完成经验校准。

后续在同一冻结开发集上完成[效果特征消融](MODULE_EFFECT_FEATURES.md)，改善了分组指标，但不构成新的独立保留验证；本报告原始结果保持不变。

本轮实现了分组校准与评估管道，执行有限小程序取得标签；没有新增数据库、TPC-C 事务或性能运行。

## 真实证据能否直接校准

现有评分对象虽然列出多个模块/契约，但都来自同一 OrderStatus 程序，且删除边界互相重叠。客户、订单、整类及共享帮助方法的“必须保留”主要来自同一份人工依赖图，不能当成独立执行过的删减案例。

审计结果：

| 项目 | 数量/状态 |
|---|---|
| 独立程序来源 | 1 |
| 有实际违约反例的确认标签 | 1，展示查询故障契约 |
| 独立确认的“不必要”标签 | 0 |
| 正常展示删减 | 有条件论证及有限运行支持，完整效果边界尚未独立核验，不强行赋 0 标签 |
| 真实数据拟合 | 不满足独立分组和双类标签要求 |

原来的 180 个计时样本不增加模块标签数量。即使把正常契约下的手工论证作为条件标签，正常/故障画像也仍属于同一源码组，不能拆成训练集与验证集来报告泛化效果。

## 固定的受控校准设计

为实际检验校准方法，而非只修改人为权重，先构造六种依赖机制的有限小程序：返回值、持久状态、异常控制、堆别名、权限检查、资源生命周期。每种机制四个变体，共 24 个候选；同一机制全部放在同一来源组。

这些是[明确编写的小程序](../prototype/module_pruning/calibration_suite.py)，不是反编译 Java/JDBC 的新实例，也不代表真实候选的抽样分布。状态/资源等概念由有限 Python 状态表达，没有模拟真实数据库内核。

每个契约的输入域显式有限：值为 -1、0、1，另有一个布尔标志；其中一个正常执行契约仅允许值 0。逐一执行原程序和跳过目标模块的程序，比较完整约定观察：

- 只要有一个合法状态结果不同，标签为 1，并保存具体反例。
- 该有限域全部相同，标签为 0。这个 0 来自穷举其完整域，不能推广到域外输入。
- 总计 140 对完整域比较，另有 24 对有限探针比较，共 328 次小程序求值。

概率输入只允许两项旧软证据：返回值是否被丢弃、有限探针是否一致。真标签、反例、机制名称和完整状态比较不传给预测器。已知依赖的硬性否决机制不参与此处软评分性能比较，真实评分器中的保护保持原样。

有限探针固定为值 0、标志 true，刻意覆盖中性状态，用于挑战“正常探针通过就能认为不必要”的推断。所有 24 个候选都通过这一探针；穷举后有 12 个必要、12 个不必要。这是人为构造的平衡挑战集，**不是实际部署中必要模块比例为 50% 的证据，也不是说任意测试都没有区分力。**

协议在运行前写入[固定配置](../prototype/module_pruning/calibration_protocol.json)。本轮没有根据结果增加机制、调整参数或更换特征。

## 校准方法与防止证据泄漏

不继续假设两项软证据条件独立，而是对布尔证据组合建立联合校准表。每个训练机制的总权重为 1，组内四个变体各占 1/4。固定平滑参数 α=β=1：

```text
q(cell) = (该证据格中必要标签的权重 + α)
          / (该证据格的总权重 + α + β)
```

这是加权平滑频率估计，不能把分数权重计数解释成具有严格独立样本含义的贝叶斯可信区间。验证时没见过的证据格回退到训练组的平滑必要比例，不读取留出组标签。

采用“留出一个完整机制组”的六折评估：每折在五组上拟合，对第六组预测。禁止按事务、输入状态或同源码变体随机拆分。保留三个对照：

1. 冻结的 v0 中心软分数：先验 0.5，弃用返回值 BF=0.5，有限探针通过 BF=0.8。
2. 只用该折训练组的必要比例，不使用软证据特征。
3. 本轮联合证据校准表。

预测器只接收特征；单元检查确认修改某个留出组的标签不会改变该组的预测。来源 ID 重复或标签未知会拒绝拟合；复制整组变体不会增加该组总权重。

六组仍是人工设计的相关机制集合，不能视为六个独立真实软件系统。此处没有声称盲测或进行独立团队标注。

## 分组留出结果

Brier 分数与对数损失均越低越好，以下先在每个留出组求均值，再对六组平均：

| 方法 | Brier | 对数损失 |
|---|---:|---:|
| 冻结 v0 手工软评分 | 0.283951 | 0.768270 |
| 训练组必要比例 | **0.250000** | **0.693147** |
| 联合证据校准 | 0.250333 | 0.693814 |

联合校准比手工评分好，但数值上没有超过简单比例基线。与基线的差距很小，未进行显著性论证；按预设规则不升级模型。

旧模型给 21 个“弃用返回值且探针通过”的候选统一预测 28.6%，该格实际有 10 个必要模块（47.6%）。这些变体并非 21 个独立程序，不能据此给出实际风险的统计置信范围；它们只说明旧假设在此挑战集中过度降低了必要性判断。

另一个明确发现是：`limited_probe_pass` 在所有候选上都为 true，没有足够变化来识别“通过”这项证据究竟多有用。因此本轮不能给旧 BF=0.8 一个可靠的新实测值。校准器只是把输出拉回接近训练比例，尚未从当前两项证据中获得跨机制的额外区分能力。

全套受控样本上的拟合表另存为 `fixture_model.json`，仅用于检查模型结构，不用于报告留出性能。它明确限定有限程序域；输入真实 OrderStatus 域时返回 abstain 和空概率。这个域检查是显式配置的边界，不是学习出的域外检测器。

## 对研究的影响

本轮完成的是**第一轮受控校准验证**，不是给真实系统的 28.6% 数字加上“已校准”的标签。原 `risk_model.json` 前后摘要一致；错误损失、实测收益、验证探针的检测率及成本都没有被本轮校准。

结果提示，应先补充能够区分隐藏状态/异常依赖的效果证据，再研究概率映射。继续修改先验数字或重复正常事务，不能解决特征本身缺少信息的问题。真实校准还需要不同程序或独立职责区域的案例，以及可审查的能力契约和删减标签；不能直接用“未发现反例”充当不必要标签。

本轮保留上述负面结果并停止，不追加特征或样本追求胜出，也不自动部署拟合表。

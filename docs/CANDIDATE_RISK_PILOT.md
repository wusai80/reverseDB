# 候选风险模型：四个融合版本的开发对照

2026-11-06。完成一次固定的简单逻辑回归对照，没有增加语义判定规则。**两个区域内的版本排序正确，绝对分数却仍受区域差异影响。** 本结果是已知缺陷上的回顾性开发诊断，不是独立泛化或概率校准。

## 范围与方法

选择 NewOrder 与 Payment 各一个历史融合版和时间绑定修复版，共4个候选。标签仅来自同一冻结时间 ABI 验证中的普通／极大时钟对照：原版与候选的返回、SQL 结果、完整九表状态是否出现差异。NewOrder 每版2对，Payment 每版4对；GC/BC及不同时钟不拆成新模块样本。原来的62条回放与其他验证不混入本次标签，业务中止检查也未混入这一子集。

从四份冻结 Java helper 中自动计数两个特征：

1. JDBC 参数绑定调用数量；
2. 绑定参数表达式中的 `toString()` 调用数量。

仅作这四份生成源码的词法计数，忽略注释和字符串内容，不是完整 Java 解析器或语义分析器。提取函数不读取版本名称、验证结果或安全标签；JSON 参数的必要文本转换也照常计数，不人工区别“好转换”和“坏转换”。特征提取先于加载结果，但研究者已知历史反例，不能据此声称盲测。通用调用图／控制依赖特征尚未在本轮提取。

复用既有逻辑回归的损失、梯度、Hessian和线性求解实现，固定正则强度1、训练内中心化、训练先验截距；不设权重方向，不搜索参数。每个训练区域总权重为1，版本各占一半。预测的是指定验证协议发现差异的开发分数，不能解释为全能力错误概率。

| 候选 | 绑定数 | 参数文本转换数 | 该验证批次发现差异 |
| --- | ---: | ---: | ---: |
| NewOrder 历史版 | 5 | 2 | 1 |
| NewOrder 修复版 | 5 | 1 | 0 |
| Payment 历史版 | 15 | 1 | 1 |
| Payment 修复版 | 15 | 0 | 0 |

四项只有一个项目来源，**原先按项目留出的主评估仍不可执行，未修改样本清单的划分要求**。这里另作明确标注的次级开发诊断：用 Payment 两版训练、NewOrder 两版观察，再反向一次。同一区域的历史／修复版本始终在一起。然而两个区域共享同一次时间修复机制，跨区域并不能消除这一信息关联。

## 结果

| 留出区域 | 历史版分数 | 修复版分数 | 区域内排序 |
| --- | ---: | ---: | --- |
| NewOrder | 0.5873 | 0.5294 | 历史版更高 |
| Payment | 0.4706 | 0.4127 | 历史版更高 |

| 方法 | 平均 Brier（越小越好） | 平均 log loss |
| --- | ---: | ---: |
| 相同训练样本的先验 | 0.250000 | 0.693147 |
| 固定逻辑回归 | 0.225267 | 0.642931 |

两折的参数文本转换计数权重均为0.23531，由拟合得到。绑定数在各自训练区域内不变，权重为0；模型没有学到绑定规模的风险贡献。四个测试候选都具有训练中未见的绑定数，两个还具有未见的转换计数，预测因此包含外推。零权重和未见取值已记录。

两个区域内均能把历史失败候选排在修复版前面，但若直接套0.5阈值，NewOrder修复版仍被判高风险，Payment历史失败版却被判低风险。这说明局部排序改善与绝对风险校准是两件事；本轮未据结果调阈值。

该改善只针对4个已知版本，同源修复、事后特征选择和不同分支数均限制其解释。文本转换并非普遍有害，例如 NewOrder 修复版仍必须序列化完整订单行。不能把正权重转成“删掉所有 toString”规则，也不能将本次指标与旧7例模型直接比较。

## 检查与停止点

六类检查通过：归档哈希；注释／字符串内容／helper重命名不影响特征；原版与候选结果完整配对；留出标签不进入拟合；训练常量特征权重为0；全常量特征回到先验。复用数值实现的8项既有测试通过。新模型没有部署，也没有改动样本清单的真实训练准入状态；本轮无数据库执行、性能测量或数据裁剪。

本轮按预定两折停止。下一研究缺口是：能否用不依赖具体转换名称的跨边界表示变化特征，在不同缺陷机制上保持排序；需要包含必要转换的正确候选及无文本转换的错误候选作为区分，而不是继续围绕这一修复调权重。

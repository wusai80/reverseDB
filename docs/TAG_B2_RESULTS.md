## 实现与语义边界

[tag_counts_b2.py](../prototype/aggregate_reattach/tag_counts_b2.py) 是手工 B2，实现[绑定报告](TAG_BINDING_AUDIT.md) 中的单个入口：active superuser、全部 Tag、按主键排序、立即返回 `(pk, document_count)` Python 整数序列。运行在冻结镜像、新建隔离数据库和固定数据阶段，没有接入完整 API。

执行流程：

1. 用原 ORM manager 和 `permitted_document_ids(user)` 构造原分组查询，保留两个 IN 条件及 `COUNT(DISTINCT document_id)`。
2. 编译目标键查询与计数查询，参数按其在最终 SQL 中出现的顺序传递。编译不访问数据库，不把授权 ID 或聚合结果转为 Python 列表/字典。
3. 将分组 SQL 放入 counts CTE，通过 LEFT JOIN 回填，缺失值使用 COALESCE 得到零，最终按 pk 排序。
4. 一次执行后将最终结果转为 Python 整数序列。消除的是中间计数映射和 CASE 参数展开，最终输出仍需取回应用。

实际分组 SQL 在八组场景中均与原 helper 第一条 SQL **逐字相同**；测试同时检查参数保持。外层连接为每键唯一的计数关系，按[契约推导](AGGREGATE_REATTACH_CONTRACT.md)保留零计数行和目标行多重性。SQL 标识符来自固定别名和 ORM 编译结果，值通过参数绑定；该实现没有任意输入 SQL 接口。

普通用户、停用 superuser、无用户等未准入身份回到原 helper。回退判定发生在执行候选 SQL 之前；SQL 执行错误直接传播，不以异常重试原路径。环境冻结、查询副作用和快照前提由实验控制，不是这些身份检查自动证明的属性。本模块不应作为通用生产优化器使用。

## 正式对照

随机数据生成器使用独立固定种子；pytest 调度种子固定为 42。每个场景先完成全部写入，再先后执行 B0、B2；两端读取期间无数据变更。期望计数从建数过程中的关联与删除标记独立累计，再同时比较完整序列，没有对查询返回数组重新排序。

| 场景 | Tag | Document | 关联数 | 结果 |
|---|---:|---:|---:|---|
| 全空 | 0 | 0 | 0 | 一致 |
| 有文档无标签 | 0 | 3 | 0 | 一致 |
| 有标签无文档 | 4 | 0 | 0 | 一致，全部零 |
| 关联文档全部软删除 | 4 | 3 | 12 | 一致，全部零 |
| 无关联 | 4 | 3 | 0 | 一致，全部零 |
| 混合删除与跨 owner 同名标签 | 6 | 9 | 28 | 一致 |
| 稀疏关联，seed=42 | 25 | 60 | 114 | 一致 |
| 密集关联，seed=43 | 30 | 80 | 1944 | 一致 |

每组还检查：编译阶段 0 条 SQL；原实现 2 条 SQL；B2 1 条 SQL且不含 CASE WHEN；输出键与计数均为 Python int。此入口的原值回填仍会在空计数时执行目标查询，因此本轮空场景同样观察到 2→1。

测试规模仅用于小型正确性验证，不能说明数据越大越快，也不是生产负载覆盖证明。

## 错误版本与保留路径

| 检查 | 实际结果 |
|---|---|
| LEFT JOIN 错改 INNER JOIN | 零计数行丢失，差分检出 |
| 缺失值从 0 错改为 1 | 零计数变成 1，差分检出 |
| A 错改为全部关联文档 ID | 删除文档被计入，差分检出 |
| 普通用户 / 停用 superuser / None | 拒绝编译 B2，回到原 helper；结果相同且未执行 B2 CTE |

三个错误 SQL 均实际执行并与原序列比较，反例保存在原始报告中。Tag through 的唯一约束禁止重复关联，所以本轮没有伪造重复边来声称验证通用重复关系；DISTINCT 仍原样保留。

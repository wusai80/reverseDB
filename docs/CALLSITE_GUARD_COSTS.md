# 候选执行重复核验的一次限定优化

2026-11-04。本轮仅消除候选执行时的一次重复完整绑定，保留执行前的来源核验和实时 ORM/schema/事务重绑。**96 项测试通过；四个既有场景中，完整调用 SQL 数从 40 条降至 27 条，中位耗时下降 14.65%～16.83%。** 带核验路径仍显著慢于直接运行原 helper，尚不构成应用查询优化的总体收益。

## 修改与条件

此前完整调用经过三次完整绑定：创建候选时一次，执行入口重新绑定一次，底层执行器再次绑定一次。本次保留创建候选和底层执行器的两次完整绑定。

[接入层](../prototype/aggregate_reattach/callsite_binding.py)在执行入口重新读取冻结 views.py、核对提取配置、解析关系，并核对来源指纹及内层 token 与保存事实的一致性。保存事实仅用于确认候选身份，不作为当前 schema 或环境的证明。原执行器仍实时核验查询、身份、manager、源码、schema、声明与事务上下文，比较指纹，并使用新生成的 SQL 执行。源码、schema、结果均未缓存，单次使用和 SQL 故障不重试规则保留。

两条路径生成的业务 SQL 和参数完全一致；减少的 13 条语句全部来自一次目录/上下文核验。原型的业务关系变换、人工审计注册表及消费者范围没有改变。本次是执行层工程优化，不是新的关系改写算法或新颖性结论。

## 固定验收与测量

- 原有 78 项接入与关系变换测试全部回归。
- 新增 14 项必要检查：两个关系分别覆盖绑定后查询、声明、manager、profile、保存 SQL、token 的变化，以及业务 SQL 故障不重试。保存 SQL 被篡改时仍使用重新生成的 SQL；其余未满足条件的情况保留原路径。
- 4 项成本测试复用既有 Tag、CustomField 的 mixed/dense 场景，结果逐次与完整夹具期望对照；旧版与新版均确认进入候选路径。
- 旧版文件直接取自上一阶段的不可变归档，SHA-256 为 `6c542df2dbb9388fe3416f21d78a7e0e89594a7790af43a54c322c188e847754`。两版共享未修改的底层绑定器与 SQL 生成器。
- 每场景对照旧版、新版和原 helper。每方法预热 2 次；5 个时间区块，各 5 轮，顺序种子 20261104。每方法每场景 25 个样本，共 300 次。
- 计时包含新 QuerySet、候选创建、执行前核验、数据库访问、fetch 与完整结果；离线提取输入事先准备，两版仍在创建与执行时核验来源。结果断言在计时结束后进行。
- trace、调用次数统计在计时外单独采集；计时期间 query logging 和 execute wrappers 关闭。沿用冻结镜像、单进程/数据库、固定数据和无并发写入条件。

## 本机热态结果

单位 ms，完整调用中位数。

| 场景 | 旧版带核验 | 新版带核验 | 中位耗时下降 | 原 helper |
|---|---:|---:|---:|---:|
| Tag mixed | 68.235 | 58.236 | 14.65% | 1.586 |
| Tag dense | 73.773 | 61.918 | 16.07% | 3.281 |
| CustomField mixed | 68.632 | 57.083 | 16.83% | 1.557 |
| CustomField dense | 68.314 | 57.647 | 15.62% | 2.977 |

| 完整调用组成 | 旧版 | 新版 |
|---|---:|---:|
| 完整 ORM/schema/环境绑定次数 | 3 | 2 |
| 目录与上下文核验 SQL | 39 | 26 |
| 变换后的业务 SQL | 1 | 1 |
| SQL 总数 | 40 | 27 |

四个场景各自的 5 个时间区块均为新版更快。这些区块共享进程与热缓存，不是独立部署复验，不给出统计显著性或生产吞吐结论。原 helper 是判断核验成本量级的参照；本轮没有重跑所有常规强基线，也不据此声称新路径优于常规数据库优化。

## 本轮结束与待讨论难点

重复核验已经消除，验收和测量完成，本轮结束，不据结果继续追加调参。

结果明确了后续若要讨论的难点：在当前小场景中，完整核验路径仍远慢于原 helper。每次完整调用仍有两遍绑定、两遍来源解析和大量目录查询。现有证据不能精确拆分这些部分的时间贡献，也没有证明哪些核验能跨调用安全复用。若以后研究部署版本、schema 与运行环境的有效期及失效机制，需要另行限定契约；本轮没有用缓存或放宽条件隐藏这部分成本。

# 相对变换特征：减少区域偏移，保留模型盲区

2026-11-06。按“继续优化”的要求完成一次特征表示对照。模型、正则、样本、标签、权重和两折开发划分保持不变；只把绝对文本转换次数替换成相对原实现的表达式深度变化。**同一小集的跨区域偏移减小，但这仍不是独立泛化或概率校准。**

## 修改

上一轮特征统计整个 helper 的 `toString()` 次数，混合了必要 JSON 序列化和被改变的时间表示。NewOrder 与 Payment 的基线不同，导致同一个0.5阈值出现两次误判。

本轮复用现有 javac AST 原始事实，在已对应的原版／候选时间参数上计算：

`Δdepth = depth(候选值表达式) − depth(原版有效值表达式)`

其中 depth 只计算表达式树操作节点的最大层数，不按操作名称赋风险权重。原版冻结运行时把系统时钟替换成命令时钟，因此沿用既有的输入对应前提统一两端的时钟表达式。参考端是真实原版 NewOrder／Payment，不是修复后候选。

最终输入为 `[绑定调用数, Δdepth]`。对应的 JDBC setter 是否变化另行记录，未加入拟合：本批它与深度变化完全相关，同时加入会重复表示同一编辑。逻辑回归权重仍从标签学习，未添加“发生变化就拒绝”的判定规则。反转训练标签会反转学到的方向，这也在检查中确认。

仅读取原始 `original.json`、`historical.json`、`repaired.json` 的绑定和表达式，不读取旧 `matched/different_structure` 判定结果。源码与事实均绑定归档哈希。不过，AST 提取器本身仍是有限支持的静态工具，参数位置及运行时对应是已有显式前提；这不等于自动恢复了全模块语义。

## 固定对照结果

| 方法 | Brier | log loss | 0.5阈值误判数 |
| --- | ---: | ---: | ---: |
| 训练先验 | 0.250000 | 0.693147 | 不作为分类方案 |
| 上轮绝对计数 | 0.225267 | 0.642931 | 2/4 |
| 本轮相对深度 | 0.221483 | 0.636049 | 0/4 |

四个候选的相对深度分别为 NewOrder历史／修复 `1/0`、Payment历史／修复 `1/0`。两折学到的权重相同，为0.23531；两个历史版本分数均为0.52938，两个修复版本均为0.47062。绑定数仍在每折训练区域内为常量，权重为0，模型没有学到其影响。

相对表示消除了本批两个区域的特征基线差异，Brier仅改善0.00378。分数离0.5很近，不能据零误判夸大区分能力，更不能将这些数值解释为实际部署错误概率。两区域现在具有相同的特征／标签模式，属于一个已知缺陷机制的对齐演示，而非两个独立泛化证据。特征是在看过旧结果与反例之后选择的；项目留出仍因只有一个来源而不可执行。

## 必须保留的两个边界

**必要转换仍保留。** NewOrder修复版仍有一次订单行JSON序列化，它在完整业务验证中保留；时间参数相对深度却为0。模型不再因这个 helper 恰好多一次必要文本转换而抬高时间边界分数。这是选择对应边界的效果，并非已经学会识别任意必要转换。

**写入顺序仍不可辨。** 已有 NewOrder `full` 和 `early_write` 使用同一个 Java helper、相同参数表达式，只选择不同数据库函数。两项特征因此完全相同，任何只使用它们的模型都不能区分两个模式。既有实际探针保存了库存76与75的差异；本轮核验该反例并将其作为范围外控制，不混进时间协议的训练或指标。

每个 helper 只对齐了一个时间绑定，其他绑定、数据库函数体、控制依赖和顺序依赖并未被这项特征覆盖。同样深度的不同运算、输入键变化及语义等价但深度不同的重写，也不能仅凭层数判断。未知表达式拒绝产生该数值，不将未知当成0。

## 验证与停止

七类检查通过：归档与源码哈希；表达式操作改名不改变深度差；留出标签不进入训练；反转训练标签改变学习方向；常量特征权重为0；必要JSON转换不影响时间差值；真实写序反例保留。复用数值实现未修改，前轮已有8项数值测试通过，本轮未重复运行。没有新业务执行、部署、性能测量或数据裁剪。

本轮按单次表示对照停止，没有调参数或更换阈值。下一项有依据的研究问题是：能否用原版与候选之间的**依赖关系变化**作为学习特征，区分绑定相同但读写次序不同的方案。应包含保持语义的合法重排作对照，而不能直接把“有重排”设为错误规则。

# 依赖关系与交互特征的小模型对照

2026-11-06。按要求加入更多特征组合，完成一次固定对照。**关系特征与少量交互项逐步改善了这组有限模型的 Brier，但尚不足以形成风险判定。** 本轮是新建的抽象执行实验，不是对前轮四个真实Java候选扩大校准；两组指标不可直接比较。

## 样本与标签

三种机制各12个候选，共36个：先读后批量写、两个写入的次序、返回读取值与写入的次序。每种机制完整组合是否重排、是否操作同一符号键，以及加法／绝对赋值／取最大值三种更新。

原程序和候选共享同一操作集合，只改变顺序。程序由小型读写原语表示，原语及其访问摘要是人工定义的；本轮没有声称从真实Java或SQL自动提取这些结构。相同键是契约中的符号别名关系，不是根据某些测试数据恰好相等来删减依赖。

每个候选固定比较81组完整初始状态与输入，共2,916对执行。完整状态包括A、B两条记录、未访问的C记录及所有元数据；观察还包含需要返回的读取值。标签由两次实际模型执行是否出现差异产生，不从依赖特征计算标签。仅覆盖串行正常执行，无异常、事务恢复或并发。

结果为：18个不重排的候选全部一致；18个重排候选中12个一致、6个出现反例。合法对照包括不同键操作，以及同一键的加法／取最大值交换；同一键的绝对赋值交换则有反例。因而不能把“重排”或“共享状态”直接当作错误标签。这些一致性结论限于固定有限域。

## 特征组合

先记录五个单项比例：顺序反转的操作对、可能冲突的操作对、显式读取、绝对赋值、进入返回结果的读取。

再加入一个关系特征：**顺序被反转且访问存在潜在读写冲突的操作对比例**。它保留“究竟改变了哪些依赖的相对次序”，比把重排数和冲突数分别相加更具体。潜在冲突并不等于语义错误：两个可交换增量也可能读写同一位置。

最后加入三个乘积项：

- 被反转的潜在冲突 × 读取比例；
- 被反转的潜在冲突 × 绝对赋值比例；
- 被反转的潜在冲突 × 返回读取比例。

三组模型分别使用5、6、9项特征。它们都是逻辑回归的输入，所有权重由执行标签学习，没有指定“若冲突则危险”的权重或决策规则。该组交互项是明确的研究假设，不意味着已覆盖全部控制、类型、异常或状态依赖。

## 固定学习对照

三次按完整机制组留出，所有重排／别名／更新变体留在同一组。每个训练机制总权重为1，采用同一训练先验截距和固定正则强度1；不选择特征、不调阈值。9次模型拟合与每折相同训练样本的先验比较。

| 方案 | 宏平均 Brier（越小越好） | 宏平均 log loss |
| --- | ---: | ---: |
| 训练先验 | 0.169271 | 0.526692 |
| 五个单项特征 | 0.164186 | 0.514978 |
| 加入关系特征 | 0.160519 | 0.506506 |
| 再加入三个交互项 | 0.159048 | 0.503227 |

三个留出机制的Brier均按上述顺序小幅下降。相比单项模型，组合模型改善约0.00514；交互项在关系特征之上的增量只有约0.00147。没有显著性或外部泛化结论。

**不能隐去的失败：** 组合模型分数范围约0.297～0.429，全部低于0.5；如果据此放行，6个有差异的候选都会漏掉。不重排与合法重排占多数，Brier的小幅改善不等于风险识别已经可靠。本轮不改变阈值来修饰结果。留出“返回读取”机制时，相关特征在训练中全为零，权重也为零，模型无法凭空学到未出现的机制。

三个机制都是同一作者构造的小模型，不能当成三个独立软件来源。训练与留出共享原语和候选生成方式，也无法替代真正按项目留出的评估。此批不与已有真实应用候选合并，不输出部署概率。

## 验证与停止

六类执行／结构检查通过：原顺序不变；同键加法及max可交换；同键赋值存在反例；不同键重排保持观察；符号键改名不改特征；完整状态及未访问记录保留。特征在计算标签之前形成哈希快照，结果归档保留每个候选的反例和逐折系数。

初次拟合在接近最优点时遇到浮点精度问题：预期下降约`1e-17`，小于目标值的浮点分辨率。仅为目标值比较加入8 ULP舍入容差，最终梯度容差仍为`1e-10`；正则、特征、划分均未改变。9次拟合最终均满足原梯度容差，修正记录已归档。

这轮证据支持保留“关系特征＋少量交互项”作为待验证方向，尚不能支持自动裁剪模块。下一步最有区分力的问题是：真实候选上能否恢复这类关系，以及可交换与不可交换效果是否在相同观察边界下提供独立训练对照；不继续在这36例上选参数。

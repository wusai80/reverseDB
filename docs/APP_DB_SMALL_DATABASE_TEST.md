## 固定范围与实验身份

复用已锁定 PostgreSQL 18.6 镜像、PostgreSQL JDBC 42.7.4 与本机 Java；没有下载新依赖。数据库使用专用容器和 tmpfs 存储，不挂载用户数据库或既有数据卷。每组夹具准备后提交，对照在同一个 SERIALIZABLE 只读事务内完成，固定执行顺序，无随机负载或并发写入。服务器实际返回 `transaction_read_only=on`，写入探针得到 SQLSTATE `25006`。

这不是全 TPC-C 或 Paperless API 测试。数据库只有 6 张约束明确的缩小关系表：district、stock、order_line 和 targets、links、allowed。保留标量查询需要的整数类型、非空列和复合键，未复制 TPC-C 全部字段/外键；负数边界用于验证类型域，不声称它由正常 TPC-C 负载产生。

- **标量基线**：直接编译并调用归档中未修改的反编译 StockLevelService 和 Sql，源码 SHA-256 与重建归档匹配；JDBC/JSON JAR 与留存摘要匹配。
- **标量候选**：本轮手写 SQL，表达类型桥接与相关聚合；不是自动识别或生成结果。
- **分页基线**：独立 Java/JDBC 夹具，复现“分组 count distinct → 应用 map → 参数化 CASE”的计算形状。它没有调用真实 Python/Django helper，不扩大历史 ORM 绑定器的准入范围。
- **分页消费者**：显式定义为按已有唯一 row_id 排序/分页，返回完整 `(row_id,k,label,document_count)`；其中 k 可重复，label 可为 NULL。租户、可见性、关联软删除和允许文档集均是独立谓词，不能因某页测试通过而移除。

## P1：标量类型桥接

原方法先取 `n=d_next_o_id`，在 Java int32 中计算 `n−20`，再查半开窗口内的低库存商品数。候选以 district 行驱动相关聚合；没有 district 行时保留 `SQLException("Missing district")`，有 district 但没有匹配时返回 0。结果继续使用同一 JDBC `getInt` 解码。

候选下界表达式：

```sql
CASE WHEN d.d_next_o_id::bigint - 20 < -2147483648::bigint
     THEN d.d_next_o_id::bigint - 20 + 4294967296
     ELSE d.d_next_o_id::bigint - 20
END
```

对应关系不是根据样本拟合：对任意 int32 n，宽整数 z=n−20 的范围为 `[-2147483668,2147483627]`，至多发生一次下溢。若 z 低于 int32 下界，加 `2^32` 正好得到 Java 的有符号回绕结果；否则保留 z。中间量处于 bigint 范围内。这个算术论证仍依赖已绑定的 int32/非空输入与原比较、缺失分支及最终解码，不能推广为任意程序等价证明。

11 组对照包含：地区缺失、存在但空数据、普通非空，以及 n 取 `INT_MIN`、`INT_MIN+1`、`INT_MIN+19`、`INT_MIN+20`、0、19、20、`INT_MAX`。普通与边界夹具同时包含重复商品、窗口端点、等于阈值的库存、其他地区/仓库的行。成功结果还与独立读取原始行后在 Java 中筛选去重的 oracle 对照。

比较内容包含数值、返回 Java 类型；缺失分支比较异常类、消息及 SQLSTATE。候选没有忽略缺失地区异常；未实施网络故障、取消或资源耗尽的等价验证。

## P1/P2：明确消费者下的四臂对照

| 方案 | 应用 map/CASE | 聚合输入域 |
|---|---|---|
| 原路径 | 保留 | 全部有效目标键 |
| 仅 P1 | 以唯一聚合关系 LEFT JOIN 代替 | 全部有效目标键 |
| 仅 P2 | 保留 | 当前页所需键对应的全部有效关联 |
| P1+P2 | LEFT JOIN | 当前页所需键对应的全部有效关联 |

三组数据状态为空目标、目标存在但无关联、混合关系；每组固定使用 `(offset,limit)` 为 `(0,0)`、`(0,1)`、`(1,2)`、`(3,2)`、`(99,2)`、`(0,100)`，共 18 组。混合关系包含重复目标键、重复关联、重复允许文档、零计数、NULL 标签、不可见目标、未授权文档、已删除关联和另一个租户。

每组比较四臂的完整有序行、返回行中每列的 JDBC 类型和非空值的 Java 类型；另用独立扫描/集合计算的 oracle 核对值。通过 row_id 区分目标行出现，需求键去重没有丢掉重复目标行。10 组带状态快照的标量对照及全部 18 组分页对照记录前后六表内容不变；其余只读检查同样由数据库只读事务约束。

混合数据全部聚合的有效关联输入是 7 行。页面 `(0,1)`、`(1,2)` 保留 3 行输入，`(3,2)` 保留 1 行；空页保留 0 行；全页仍为 7 行。这是额外查询得到的**逻辑输入数**，不是执行计划扫描数、耗时或生产收益。

## 错误版本必须失败

| 错误变换 | 本轮实际观察 |
|---|---|
| 去掉 DISTINCT | 原计数 2，错误计数 3 |
| 半开窗口改为包含上界 | 原计数 2，错误计数 3 |
| 下界直接拓宽 bigint，不保留回绕 | 原计数 0，错误计数 1 |
| 直接 SQL int32 减法 | 原计数 0，SQLSTATE `22003`，integer out of range |
| 地区缺失被 COALESCE 成 0 | 原抛 Missing district，错误版本返回 0 |
| 计数排序前先按 row_id 截页 | 正确第一行 row_id=8，错误第一行 row_id=1 |
| 遗漏全局计数消费者 | 完整计数总和 8，裁剪后为 4 |

消费者描述符来自夹具显式声明，不是自动源码分析。`base_order_page` 接受并进入候选；`count_order`、`global_count` 拒绝，未知描述符保留 unknown。这三类走原路径并比较完整的夹具响应，全局消费者包含 total 字段；未知描述符只验证保守路由，不声称恢复了未知业务语义。

## 本轮结论与停止线

本轮为两项形式义务提供了真实数据库支持：原语言整数语义可以在受限关系表达式中保留；明确的单生产者消费者需求可以缩减派生计算域，同时保留重复、类型和权限谓词。错误版本检查证明这些样例确实区分了相近但错误的规则。

尚未完成：通用程序分析/自动 SQL 生成、完整 Django 或 TPC-C 能力等价、真实 Tag 树消费者、生产权限/RLS、并发调度和故障透明性、实际成本选择或性能测量。有限测试并未替代全输入等价条件。实现仍是实验副本与手写受限模板。

小规模测试到此结束。结果足以进入既定的成本验证准备，但本轮不继续追加数据规模、优化规则或计时。

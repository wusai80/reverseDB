# 模块删减收敛审查

2026-11-05。**两个真实来源的依赖提取阶段已完成；当前四个源码区域全部保留，没有新增删除候选或可用于真实应用的概率模型。** 这不是否定既有条件标签，而是把它们放回各自的能力契约中。业务数据完整、保留能力完整，成为后续工作的固定前提。

本轮只审查已有证据，不运行应用、数据库或性能实验，不追加特征或拟合。审查不改变历史标签，也不将本轮一致性核验算作新的泛化样本。

## 固定研究对象

目标是去除不服务于保留能力的**执行模块及其专属依赖**。模块可以是方法、具有完整效果边界的区域，或方法与专属 SQL 的组合；不能仅因某个字段或记录未出现在测试中，就把它当作可删模块。

令 C 为明确的能力/环境契约，R 为保留入口，O 为保留观察，D_C 为原程序在 C 下允许的完整业务状态域，I_C 为合法请求域。候选变换 T 应满足：

```text
对所有 D ∈ D_C、i ∈ I_C、r ∈ R：
    O(执行(P, r, i, D)) = O(执行(T(P), r, i, D))
```

两臂必须使用相同完整初始数据。D_C 和 I_C 不能根据测试命中情况缩小；读写应用还须比较约定的完整逻辑提交状态。这里的“完整”不禁止业务本来就要求的更新或删除，而是要求变换前后保留相同的合法数据处理能力。样本仅提供回归证据或反例，不能替代上述量化条件。

O 应明确包括响应的值、类型、顺序、重复项、所需错误语义及数据库效果。对象身份若影响这些观察，就属于正确性义务；无法证明时保留模块，不另开对象去重/数据裁剪优化。既有正常执行契约不会自动适用于任何新模块；环境假设须逐候选绑定。

### 八条既有记录如何解释

| 区域 | 禁用该能力的历史契约：标签 / 比较对数 / 差异数 | 启用该能力的历史契约：标签 / 比较对数 / 差异数 | 保留现有能力时 |
|---|---|---|---|
| 格式化路径 | 0 / 24 / 0 | 1 / 24 / 24 | 保留 |
| 普通文件名 | 0 / 24 / 0 | 1 / 24 / 24 | 保留 |
| 自定义价格 | 0 / 48 / 0 | 1 / 192 / 48 | 保留 |
| 价格原因 | 0 / 48 / 0 | 1 / 192 / 48 | 保留 |

四个 0 均来自**契约明确禁用功能所导致的不可达论证**，并有回归支持。它们不是“有限测试没碰到”的标签，但也不是保持当前能力时的优化机会。当前没有采纳关闭命名/价格能力的产品契约，不得为了得到负例而把这些功能关掉。Saleor 禁用契约实际同时关闭价格和原因两个标志；不是仅禁用表中单个字段。

四个 1 有边界内实际删除反例。两个命名方法被选中后，删除会导致构造查找失败；两个价格区域被删除后，对象状态/队列发生差异。Saleor 使用声明的对象适配器，未运行真实 ORM 提交，因此不能扩大为数据库效果证明。

合计仍为两个来源组、四个区域、八条成对契约、576 对比较。两套提取器对各四条旧契约的一致性检查，不增加标签数量；同区域启用/禁用记录不能拆开充当独立训练与验证系统。

## 哪些结论已成立

证据按用途区分，不把它们压成一个“可信度高低”的数字：

| 证据种类 | 已有依据 | 能支撑什么 | 不能支撑什么 |
|---|---|---|---|
| 源码条件论证 | 固定选项/普通 DTO 守卫导致区域不可达 | 声明契约下的删除条件 | 自动缩小产品能力或合法数据域 |
| 边界执行反例 | 原版成功、删除版不同 | 否定该边界下的直接删除 | 自动证明公开 API 可达或全数据库效果 |
| 自动结构关系 | 策略绑定、控制守卫、字段写入、入列与投影 | 给出来源明确的可能依赖 | 完整效果摘要、全输入等价或新预测准确率 |
| 旧 OrderStatus 删减实验 | 完整 JSON/九表摘要一致，读取 5→4，固定场景耗时下降约 18%–22% | 正常只读受限流程中，移除已执行冗余模块可减少工作 | 任意异常等价、TPC-C 吞吐或跨系统加速 |
| 概率模型实验 | 七个完整有限案例的固定分组对照 | 暴露当前特征/来源不足 | 真实应用已校准概率或自动删除许可 |

OrderStatus 是目前与项目核心最接近的实例：删掉已执行但返回值被丢弃的展示方法和专属查询，保留完整明细与数据。但原终端入口确实消费它；删除查询还存在“原版报错、删除版成功”的故障反例。它依赖明确的入口与正常执行契约，且手写候选此前已经省略同一调用，不能再当作新发现或独立复现。[原实验与边界](MODULE_PRUNING_PILOT.md)。

Paperless/Saleor 是原始源码上的依赖验证，不能称为新增反编译验证。当前四个条件负例本来不可达，未做计时；删掉静态代码不能直接等同于减少已执行工作或得到加速。

## 模型与方法的收敛决定

八条真实契约记录继续 `abstain`，全应用标签和概率为 null，训练准入与删除授权均为 false。新关系结构尚未与旧有限夹具特征域建立可靠映射，不能通过手工填写布尔值绕过这一缺口。

共享模型在既有七例上，加控制特征后的 Brier 为 0.240388，仍差于训练先验 0.237269。这不支持继续在同一小集上调权重、阈值或换模型追求胜出。概率可以在未来为审查排优先级；已知必要依赖和未闭合效果不能被低分或收益抵消。[固定模型结果](MODULE_SHARED_RISK.md)。

当前方法主张可收敛为：**能力契约固定 → 模块职责边界 → 来源绑定的保守依赖闭包 → 删除义务 → 差分反证与成本验证。** 尚未证明通用自动化或学术新颖性。可能的研究贡献应落在反编译边界与应用—数据库效果之间的需求连接，而非把标准逻辑回归包装成新算法。

## 下一阶段只保留一个验收目标

寻找一个“实际执行，但不服务于任何保留输出/效果”的独立模块候选，验证同一删减论证能否迁移。能力、完整数据域和观察先固定；不能用关闭功能来制造候选。模块边界须包含其初始化、异常及专属数据库依赖，共享依赖保留。

采取一次有界筛选：只检查已有 Paperless/Saleor 两个来源，不增加仓库，最多选一个候选。候选须同时具备执行路径证据、无保留消费者的理由、可列明的效果义务和可隔离的删除边界。达不到条件就记录“本范围无合格候选”并结束，不自动扩大范围或重复调分；有候选也先讨论最小未闭合义务，不能直接删除。

通过上述门槛后才制定一次固定的原版/删除版比较；两臂输入、完整数据和保留能力相同，有反例即保留，有未知即停止准入，语义通过后才测成本。对象身份仅作为义务，不追加对象去重或裁数据实验。这个验收目标不承诺一定能找到可删模块或得到提速。

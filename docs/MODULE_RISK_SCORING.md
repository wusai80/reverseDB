# 模块必要性的概率评分原型

2026-11-04。已实现可运行的贝叶斯评分、收益/损失排序和下一项验证建议。原型读取现有模块证据，不执行删减，也不新增数据库或性能实验。

后续已完成[第一轮受控校准](MODULE_RISK_CALIBRATION.md)：未超过简单比例基线，未替换本报告中的未校准参数。

**这是未校准的假设模型。** 先验、似然比、错误损失及验证区分能力均公开配置；输出的范围是对这些假设的敏感性分析，不是置信区间、可信区间或经过验证的正确率。

## 1. 概率的对象

对指定能力契约 C、指定模块及删减方式，令 H 表示“删除将违反至少一项保留能力”。计算：

```text
q = P(H | C, E)
```

这里估计的是对模块必要性判断的不确定性，不是模块执行频率、测试覆盖率或下一笔事务失败的频率。结论也不是说任何实现都离不开某个 Java 类：替代实现或不同删除边界属于不同问题。

契约标识由保留入口、观察与已声明条件的规范化内容生成。当前正常执行画像和允许查询故障的画像有不同标识；证据必须同时匹配模块与契约。已有故障反例不会被丢弃，但不能不区分契约地计入正常执行画像。

## 2. 贝叶斯更新与相关性处理

以赔率形式更新：

```text
odds(q) = odds(prior) × ∏ BF(group)
BF(group) = P(E_group | H, C) / P(E_group | not H, C)
```

当前显式参数如下，均为原型假设，未从现有实验拟合：

| 参数 | 低 / 中心 / 高 | 含义 |
|---|---|---|
| 必要性先验 | 0.25 / 0.50 / 0.75 | 表达缺乏经验校准时的多种起点 |
| 静态结果用途证据的 BF | 0.25 / 0.50 / 1.00 | 弃用返回值及受限消费者信息的整体贡献 |
| 完整差分活动的 BF | 0.50 / 0.80 / 1.00 | 旧实验整体结果的贡献，不按调用次数累加 |

低于 1 的 BF 倾向“不需要”，等于 1 表示不提供区分力；算法也支持高于 1 的反向软证据。缺少证据时保持先验，不把 unknown 编成 0 风险。

两个证据组在给定 H 后的条件独立性是当前模型假设，并未由数据证明。组内多项观察作为一个整体；相同 ID 重复输入会去重，同一组即使有不同 ID 也只更新一次。同一 ID 出现相互冲突的内容会报错。人工分组错误和跨组相关性仍是限制，程序不声称能自动发现全部重复含义。

因此，原有 8 组对照及 180 次计时调用只贡献**一个差分证据组**。不能通过重跑相同成功输入，不断把概率压低。

中心配置计算一个 q；枚举先验和所用 BF 的低/中心/高组合，得到敏感性包络。展示模块有 27 个组合。这个范围只覆盖所列假设，不是对全部模型误差的保证。

## 3. 已知反例与必要依赖

概率不是用来抵消明确冲突：

- 给定依赖契约中存在必要路径，标记 hard_block，并以 q=1 表示该约束下的阻止状态。
- 同一模块、同一契约下已有实际违约反例，同样阻止删除。
- 上述 q=1 是由契约事实/反例覆盖软更新的结果，不是有限样本拟合出的 100% 经验正确率。
- 任意高的预期收益也不能让这些候选进入删除候选排序。

必要路径目前来自已有人工绑定需求图；概率算法没有使这个来源自动变成完备证明。所有输出的 `deletion_authorized` 均为 false。

## 4. 收益与风险排序

实现用户讨论的效用形式：

```text
Score = (1-q) × G - λ × q × L
```

G 是指定变换的预期收益，L 是错误删除损失，λ 是风险权重。当前展示模块的 G 复用旧实验三个场景的中位耗时差，约 0.304 / 0.428 / 0.434 ms（最小/中位/最大）；这不是统计置信范围。

为了使第一版可计算，L 暂设为 10 个“毫秒等价效用单位”，λ=1。这是人为政策权重，**不表示一次能力损失实际只值 10 ms**。更换权重应重新报告敏感性；目前没有部署级效用结论。

中心及敏感性范围均输出；同一契约内按最保守效用、再按中心效用排序。未知收益保留 null，不伪造为零；实测负收益允许保留。不同契约分开排序，避免将要求不同的方案混在一起比较。

## 5. 用概率指导有限验证

对下一项检查 t，设 s=P(发现违约 | H,C,E)，f=P(发现违约 | not H,C,E)。用二元熵计算：

```text
IG(t) = H(q) - P(阳性) H(q | 阳性) - P(阴性) H(q | 阴性)
priority(t) = IG(t) / cost(t)
```

本轮仅提供“外部效果审查”“独立状态族”“重复既有输入”三个假想检查。s、f 和成本都是显式未校准参数，成本单位是抽象验证预算；不是已经估计出了真实检测率。

预算固定 3 单位，过滤超预算项后，按最保守信息增益/成本排序，一次最多建议一项。没有实施多检查组合求解，也没有自动调用工具执行建议。对于已观察过的相同确定性输入，设新增区分力为 0，防止继续推荐重复计时。

## 6. 当前案例结果

| 候选 | 输出 | 解释 |
|---|---|---|
| 展示方法 + 专属 SQL，正常执行契约 | q 中心 **28.6%**，假设敏感性 **4%～75%** | 只是当前先验/BF 下的估计，尚未校准 |
| 同一展示模块，允许查询故障契约 | hard_block | 旧故障注入已经给出该契约下的反例 |
| 客户模块、订单选择模块、整类、连共享工厂一起删除 | hard_block | 现有需求图存在保留能力依赖 |
| 仅 SQL 字段 | 保持先验；无收益分数、无验证推荐 | 没有该独立变换的有效边界与实测成本 |

展示模块的中心效用约 -2.551，敏感性约 [-7.424, 0.017]，说明在当前损失权重下不应把一次已观测的加速当作删除许可。其下一检查建议是外部效果审查：假设下的最保守信息增益/成本约 0.0195 bit/预算单位，高于独立状态族的 0.00943；重复既有输入为 0。这些比较同样依赖模型假设，不是实测验证效率。

真实效用排名目前只有展示模块这一个有实测收益的非阻止候选，**不能据此宣称已经验证了多模块排序准确率**。结构候选和未知成本的结果完整保留。

## 7. 验证、证据与边界

18 项检查通过，涵盖解析可算的后验、先验保留、重复证据不累加、契约隔离、反例覆盖、高收益不能抵消必要依赖、未知/负收益、敏感性包络、风险权重、信息增益、预算、跨契约分榜、无效数值及 BF 单调性。还有对真实归档来源、静态事实、完整差分记录和故障反例的绑定检查。

这些检查验证算法行为和证据接入，不验证概率校准。以后校准需要具有独立软工审查依据的**模块删减案例**，不能用更多同一模块事务替代，也不能把“未发现反例”直接标成“不必要”。目前的先验与 BF 不应包装成研究已经证明的风险模型。

本轮实现到此结束：可评分、可解释假设、可给出一项验证建议；不增加删减模块、数据库运行或迭代调参。

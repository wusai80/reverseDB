# NewOrder 职责接口实验

此目录是实验源码，不替换 `app/tpcc/src` 或冻结重建包。只抽出库存读取、地区属性供给、数量规则与延后写入；订单构造仍使用原入口和事务框架。它是人工重构，不是未修改反编译输出或自动恢复结果。

`NewOrderStock` 每笔订单创建一次，借用调用者的 Connection：

1. 构造时接收共同事务连接与地区。
2. 按原订单行顺序调用 `stage(item, quantity)`，允许重复商品，返回当前行的地区信息；库存 SQL 更新仅排队。
3. 所有订单行已暂存且订单行批次写入成功后调用 `apply()`，执行库存批次一次。
4. `close()` 只释放自己的语句，不提交、不回滚、不关闭借用连接。任何异常由外层事务所有者处理。

旧库存、剩余量、回补规则、累计字段和 PreparedStatement 都不暴露给订单构造方。接口仍要求共享事务和调用生命周期，不能当作无状态函数或可独立部署服务。保留当前重复商品规则是本轮兼容选择，未来是否保留仍由能力契约决定。

运行：`python3 scripts/tpcc_module_split.py`。脚本将本目录源码装入新的实验包并执行 NewOrder 专项对照，详见[结果与边界](../../../docs/NEWORDER_MODULE_SPLIT.md)。
